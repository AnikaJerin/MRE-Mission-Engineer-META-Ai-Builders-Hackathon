# Researcher workflow — React UI + Python backend

## Start the software

The frontend is React with Vite; the backend is the existing Python application.
Use two terminals. The assistant authored this change but did not install dependencies,
run the project, tests, server, build or paid requests. Run the checks below yourself.

Node must satisfy the version printed in `frontend/package.json` (20.19+ in the 20.x
line, or 22.12+). See [Vite's official setup requirements](https://vite.dev/guide/).
Keep the lockfile generated by your first successful `npm install` in the repository.

**Terminal 1 — repository root / backend:**

```sh
cd /Users/anika/Documents/MRE-Mission-Engineer-META-Ai-Builders-Hackathon
source .venv/bin/activate
python -m pip install --no-deps -e .
PYTHONPATH="$PWD/src" python -m unittest discover -s tests -v
```

Then, in this same zsh terminal, set the key without printing it:

```sh
read -r -s 'MODEL_API_KEY?Paste your Meta API key, then press Enter: '
export MODEL_API_KEY
PYTHONPATH="$PWD/src" python -m mre_engineer serve --port 8769 --source-run v2 --engineering-run versioned-v3
```

The key belongs only in this backend terminal. Do not add it to React code, browser
forms, an Excel file or a `VITE_...` variable. If you start the backend without a
key, reading/importing remains possible, but assessment is unavailable. Restart the
backend after setting its environment variable. A different terminal does not inherit it.

**Terminal 2 — frontend:**

```sh
cd /Users/anika/Documents/MRE-Mission-Engineer-META-Ai-Builders-Hackathon/frontend
npm install
npm test

```

Open **http://127.0.0.1:5173**. Use that exact address; the dev proxy deliberately
accepts mutations only from that origin. Leave both terminals running. Port 5173
does not silently switch to another port. If occupied, stop the earlier frontend
with Ctrl+C in its terminal. Do the same for an older backend on 8769.

The build is optional for editing, but is a useful owner-run verification. After a
successful build, the backend also serves `frontend/dist` at http://127.0.0.1:8769
without Vite. Without a build, that address displays frontend startup instructions.
`/validation` remains the separate saved-methods/benchmark workspace.

## কী ইনপুট দেবেন?

গবেষক **New experiment** খুলে পরীক্ষার নাম, কী বুঝতে চান, কতক্ষণ electrolysis
হয়েছে এবং current দেন। Collected oxygen মাপা থাকলে mass **g**-এ দেন। শুধু এই
তথ্য থাকলেও conditional review শুরু করা যায়; অজানা তথ্য ফাঁকা থাকলে agent সেটি
প্রমাণের ঘাটতি হিসেবে দেখাবে। ফাঁকা মানকে শূন্য ধরা হয় না।

| Information | Input and interpretation |
| --- | --- |
| Name | Required experiment/run identifier |
| Question | Optional; default oxygen-accounting question if blank |
| Current | Positive constant current in **A**, or complete Excel current trace |
| Duration | Positive electrolysis duration, **hours in the form**, explicitly converted to **seconds**; Excel uses seconds directly |
| Collected oxygen | Optional nonnegative **g**, not ppm, percent or a gas volume |
| Same time interval? | Confirm explicitly; otherwise the oxygen/charge ratio is withheld |
| Context | Configuration, feedstock, electrodes, temperature in °C; keep unknown if not established |
| Measurement records | Gas method/reference conditions, calibration record locator, original records, observations and source label |
| Composition | Optional single oxide wt% analysis with ID/source and actual batch mass in g; no normalization, merging or inferred iron oxidation state |
| Absolute ± bounds | Optional current A, time s and oxygen g bounds; all three required for scalar sensitivity, not a confidence interval |
| Resources | Optional available diagnostic hours/USD and user estimates for four review options |

Electrolysis duration and total high-temperature exposure are different clocks. Put
additional thermal exposure in observations; never replace the charge integration
duration with furnace time. A calibration locator means documentation is identified,
not that the software inspected or authenticated the calibration.

## Start-to-end demo, one step at a time

1. Click **Load published example**. This is a local read, not an API call.
   It fills the Yu et al. one-hour historical reconstruction: **0.5 A**, **1 hour**,
   **0.07 g** collected, reported same interval, LHS-1, YSZ/Pt hollow anode and Mo
   cathode. Raw traces and measurement uncertainty are not invented. Edits are labelled.
2. Open **Reactor context and measurement records** if you want to inspect those
   values. Advanced fields remain collapsed until needed.
3. Confirm credit use, then click **Assess experiment** once. At most **five Meta
   requests** are attempted. $1.25 is the local reservation envelope, not a provider
   cap or necessarily the actual cost. No automatic retries occur.
4. **Follow the investigation** shows completed steps from actual saved events:
   input validation → independent arithmetic → first review → critic → final review.
   Before the first review, Meta proposes competing explanations and selects a
   permitted local tool. The critic selects a second different check. Charge accounting
   reaches the model in every completed cycle. These are five API stages with two
   actual local tool executions, not a fixed prerecorded answer.
5. Expected accounting for the unchanged example: **1800 C**, ideal oxygen about
   **0.149236 g**, apparent collected/ideal ratio about **46.9055%**. This checks
   declared charge accounting; it does not establish total generated oxygen, a fault,
   validated efficiency or reactor health. Missing gas/calibration/trace evidence should
   remain visible. Exact model wording is not a fixed expected answer.
6. Read **First review**, **After the critic**, and **What did the critic question?**
   Expand the cards for competing explanations, discriminating observations and
   prerequisites. A correct original answer may remain unchanged. A revision is not
   automatically an improvement.
7. Expand **Inspect inputs, sources, tools and numerical verification**. Check exact
   supplied values, model-selected/executed tools, references, arithmetic agreement,
   trace integrity, version, API attempts and estimated cost. Independent calculations
   do not certify free-text engineering recommendations.
8. Under **Researcher review**, enter a name, choose Accept draft / Request changes /
   Reject draft, add a reason, and save. This records a separate immutable review;
   it neither rewrites Meta's output nor authorizes hardware operation. To revise the
   inputs, start a new assessment; retain the earlier record.
9. Click **Export report** for readable HTML or **JSON** for the full evidence record.
   Browser Print → Save as PDF can save the HTML report; a native PDF generator is
   not part of this change. Export and refresh do not make API calls.
10. Click **Saved reviews** to reopen this assessment. Click **New experiment** to
    clear the form and enter a real run. This action does not reuse historical answers.

If a request fails, the partial record remains visible. Inspect the error/ledger
before an explicit new run. Stop applies before the next request; an in-flight
request can finish. Do not run a second paid terminal command at the same time.

## Excel route

1. Click **Upload Excel → Download Excel template**. The template is blank on purpose.
2. In `Experiment`, keep the `field,value,unit,source` headers. Fill only the value
   and source cells. Required: `experiment_name`, `duration_s`, and either `current_A`
   or a complete `Trace`. Use a numeric cell for numeric values. Preserve units.
3. Optional `Trace` has `time_s,current_A,voltage_V,source`. Supply 2–1000 rows, start
   at 0, finish at `duration_s`, and strictly increase time. Clear scalar current and
   voltage if using traces. Voltage must be complete and aligned, or entirely blank.
   Timezone parsing, sign inference and extrapolation are not performed.
4. Optional `Composition` has `analysis_id,oxide,wt_percent,source`. Use one analysis
   and source; keep separate assays in separate workbooks. Supply actual batch mass
   in `Experiment` to calculate represented inventory.
5. Save as `.xlsx`, at most 2 MB. Click **Choose .xlsx file**. Import validates locally
   and populates the same form. Formula cells, macro/legacy formats, external workbook
   links, unknown fields/units, invalid windows and merged analyses are rejected.
   Paste values instead of formulas. No workbook code executes.
6. Inspect the populated fields. Workbook hash and cell references are retained;
   edits are marked as user changes. Then authorize **Assess experiment** as above.

There is no arbitrary spreadsheet-column guessing. A future instrument adapter
must map explicitly into this same contract. The downloadable workbook is packaged
with the backend; no additional spreadsheet service or paid dependency is needed.

## What is in the demo, and what is planned?

Manual entry, template-based Excel import, checked accounting, actual Meta tool
selection, critique/revision, saved reviews and exports are implemented in this
change, pending your execution checks. **Connect equipment** is visibly labelled
**Planned** and does not pretend to connect to a live reactor or LIMS. See
[scope alignment and integration plan](SCOPE_ALIGNMENT.md).

Old source/engineering/T12 results are under **Validation & methods**. They explain
how bounded outputs were tested, rather than assigning an accuracy percentage to
new user inputs. Six development and six evaluation tasks have owner-reported live
results under freeze `t12-v2`; revision did not establish superiority over controls.
The new adapter has separate owner-run input/Excel/math/HTTP/loop tests; it is not
automatically validated by the earlier T12 batches.
