# Two engineering evidence investigations: frozen development protocol

Two distinct reactor contexts, six constructed review claims per case, two source
families. These are not 12 independent experiments or a 6-development/6-independent-
evaluation dataset. Both source families have already been inspected. Published
measurements, author attributions, analytical limitations and unresolved causes
are distinct. Public sources may be in pretraining; no blind discovery claim.
K4 asks whether the poster ever mentions EDS for porosity, which is directly
checkable. Its reference label does not resolve the poster's internal ambiguity
about the actual estimation method. Do not score that unresolved method as known.

Complete each case as: choose local check -> original review/next-evidence plan ->
critic chooses a different check -> critic challenge -> revised or retained review.
Five genuine Meta calls and two local tools form the main investigation. The same
initial review is the one-pass baseline. Three additional calls generate two fresh
drafts and select a control answer, with the same evidence and both returned tools.
Each branch thus uses five calls including the two shared initial calls; eight
unique requests per case, not ten. Calls match, not exact token compute. The control
also benefits from the critic-selected check, so this probes revision, not independent
tool-discovery superiority. Main client limit is five, control client three; no
automatic retries or concurrent paid operations. Two cases: at most 16 requests,
$4 local reservation envelope, not a provider cap.

Reference key is separate and never sent to Meta. Original and revised outputs
contain a complete six-claim ledger and numeric fields; source text remains visible
to all comparators. Exact supported/contradicted/not-established labels, required
reference-block coverage and independent numeric results are scored. Per-clause
semantic entailment of explanations is not scored by an LLM or keyword matcher.
Unsupported endorsement = supported label where key is contradicted/not-established.
Missed contradiction = a contradicted key not labelled contradicted. Report counts,
denominators, recall, false contradictions, abstentions, corrections/regressions and
errors without hiding unavailable outputs. Claim labels apply to the source packet,
not universal physical truth. K6 and Y6 assess correct attribution, not a new diagnosis.

Production arithmetic is compared with independently implemented Decimal/Fraction
references before paid work. This validates calculation consistency, not measurements.
Numeric tolerances cover declared output rounding; do not interpret them as sensor
confidence intervals. The numerical reference values/labels are not provided to the
model except when an explicitly selected local tool produces a result. Constants
and calculation targets are public context. No optional property/kinetic model used.

Preserve every raw plan. Release checks may block a plan's use for engineering
endorsement when structured claims/numbers fail; blocked outputs stay visible and
do not receive improved raw scores. Passing the checks releases a draft for document
review only, never hardware operation or a validated optimal experiment.

Plan quality, prose correctness outside the ledger, actual lab utility and researcher
time savings remain unscored without applicable outcome evidence. Completing two
runs establishes two bounded end-to-end engineering evidence workflows, not reactor
qualification or proven general engineering advantage. No personal interview required.
